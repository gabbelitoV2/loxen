## Camera key-value observation (KVO, packages com.moblin.android.platform.core and com.moblin.android.platform.avfoundation)
- `device.observe(\.lensPosition) { [weak self] device, change in ... }` on an `AVCaptureDevice` -> `device.observe(AVCaptureDevice::lensPosition) { device, change -> ... }`, which returns a `com.moblin.android.platform.core.NSKeyValueObservation` with `invalidate()`. `options: [.initial, .new, .old]` -> `options = setOf(NSKeyValueObservingOptions.initial, NSKeyValueObservingOptions.new, NSKeyValueObservingOptions.old)`; `change.newValue`/`change.oldValue` are nullable. Drop `[weak self]` and `guard let self`.
- Only `lensPosition`, `iso`, `exposureDuration` (`Long` microseconds) and `deviceWhiteBalanceGains` notify; they follow the running camera. The handler runs on the camera thread and only when the value changes, like KVO on iOS, so keep Swift's `DispatchQueue.main.async` (-> `mainScope.launch`).
- A stored `NSKeyValueObservation?` holding such an observation -> `var o: NSKeyValueObservation? by NSKeyValueObservation.holder()`. Android has no deinit; the holder invalidates the observation it drops, so `o = nil` and assigning a new observation stop the old one as on iOS. `inputGainObservation` stays `Any?` with `observeInputGain` (T5).
- `AVCaptureDevice.currentISO` and `AVCaptureDevice.currentExposureDuration` keep their names; pass them to `setExposureModeCustom(duration = ..., iso = ...)` as in Swift.
