## Tesla protobufs (PB, package com.moblin.android.integrations.tesla.protobuf, runtime com.moblin.android.platform.swiftprotobuf)
- `tools/pbswift.py` generates every type of `Moblin/Integrations/Tesla/Protobuf/*.pb.swift` under its Swift name, so they always exist; never write `TODO()`, `Any` or stand-ins for them and never edit that directory. Nested types are nested classes: `CarServer_HvacSeatHeaterActions.HvacSeatHeaterAction`, `CarServer_ClosuresState.OneOf_OptionalLocked`. `SwiftProtobuf.Google_Protobuf_Timestamp` -> `Google_Protobuf_Timestamp` (seconds `Long`, nanos `Int`) from the runtime package.
- Messages: `var m = X()` / `X.init()` / `.init()` -> `val m = X()`; `try X(serializedBytes: data)` -> `X(serializedBytes = data)` (throws `BinaryDecodingError`); `try m.serializedData()` -> `m.serializedData()` and `try m.merge(serializedBytes: d)` -> `m.merge(d)` (import both from the runtime package); `X.with { $0.a = 1 }` -> `X.with { a = 1 }`, and `this.a = a` when a local or parameter has the same name; `==` stays `==`. `jsonString()` and `textFormatString()` do not exist: log `m.toString()` (type name and serialized bytes in hex) instead.
- Field types: `Bool` -> `Boolean`, `Int32` -> `Int`, `UInt32` -> `UInt`, `Int64` -> `Long`, `UInt64` -> `ULong`, `Data` -> `ByteArray`, `[T]` -> `MutableList<T>`. Unlike the rest of the port these fields really are `UInt`/`ULong`: `m.flags = 1 << E.x.rawValue` -> `m.flags = 1u shl E.x.rawValue`, `s?.counter += 1` -> `s?.let { it.counter += 1u }`, `UInt8(m.counter)` -> `m.counter.toInt().toByte()`, a Swift `UInt32` local that receives one stays `UInt`.
- An implicit Swift enum member (`.rrorNone`, `.cloudKey`) gets the exact generated type of the field it is assigned to or compared with, prefix and `_E` suffix as in Swift: `signedMessageStatus.signedMessageFault` is `UniversalMessage_MessageFault_E`, `signedMessageStatus.operationStatus` `UniversalMessage_OperationStatus_E`, `CarServer_ActionStatus.result` `CarServer_OperationStatus_E`, the `VCSEC_ClosureMoveRequest` fields `VCSEC_ClosureMoveType_E`, `keyFormFactor` `VCSEC_KeyFormFactor`, `keyRole` `Keys_Role` and `VCSEC_SignedMessage.signatureType` `VCSEC_SignatureType`. The other `_E` enums are `Errors_GenericError_E`, `VCSEC_ClosureState_E`, `VCSEC_OperationStatus_E`, `VCSEC_RKEAction_E`, `VCSEC_SignedMessage_information_E`, `VCSEC_UserPresence_E`, `VCSEC_VehicleLockState_E`, `VCSEC_VehicleSleepStatus_E` and `VCSEC_WhitelistOperation_information_E`; never drop the suffix or guess another prefix.
- Enums are `enum class E(val rawValue: Int)` with the Swift case names plus `UNRECOGNIZED` (rawValue -1) for unknown wire values: `E(rawValue: n)` -> `E.fromRawValue(n)` (never null), `E.allCases`, `E()` -> the first case, for example `UniversalMessage_Domain.broadcast`. A `switch` over one needs an `else` or `E.UNRECOGNIZED` branch in `when`.
- Nested mutation works as in Swift and needs no temporaries: `message.toDestination.domain = d`, `message.signatureData.aesGcmPersonalizedData.epoch = e`, `action.vehicleAction.getVehicleData.getChargeState = CarServer_GetChargeState()`. Reading an unset message field returns a default that joins its parent only when it is mutated, so reads never set presence or switch a oneof. `hasX` / `clearX()` exist exactly where Swift has them.
- Oneofs are sealed classes with one class per Swift case, same lowercase name, holding `value`: `guard case let .routingAddress(a) = m.toDestination.subDestination else { return }` -> `val a = (m.toDestination.subDestination as? UniversalMessage_Destination.OneOf_SubDestination.routingAddress)?.value ?: return`; `if case let .speed(s) = d.optionalSpeed` -> `(d.optionalSpeed as? CarServer_DriveState.OneOf_OptionalSpeed.speed)?.let { s -> ... }`; `switch m.payload { case .a(let v): ... case nil: ... }` -> `when (val p = m.payload) { is X.OneOf_Payload.a -> ... p.value; null -> ... }`; `m.payload = .sessionInfo(d)` -> `m.payload = X.OneOf_Payload.sessionInfo(d)`. The per-case properties (`m.sessionInfo`, `d.speed`) read and write like Swift.
- Value semantics: assigning a message to a field, a oneof or a list element, and `list.add(m)`, store a copy, like Swift. Reading returns the live stored instance, so when Swift copies a message into a `var` and then mutates only the copy (`var s = m.sub; s.x = 1` with `m` meant to stay unchanged) write `val s = m.sub.copy()`. An `inout` message parameter is the instance itself. Treat `ByteArray` values as immutable; copy one before changing it in place.
