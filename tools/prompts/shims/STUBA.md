## System colours, Photos authorization and back cameras (STUBA, packages com.moblin.android.platform.uikit and com.moblin.android.platform.avfoundation)
- `Color(UIColor.secondarySystemBackground)` -> `UIColor.secondarySystemBackground` (import com.moblin.android.platform.uikit.UIColor), already a Compose `Color` that follows light and dark mode; never a hard-coded `Color(0xFFF2F2F7)`. The `UIColor` type and other `UIColor(c)` values stay a Compose `Color`; the object has no other members.
- `PHPhotoLibrary.requestAuthorization(for: .readWrite) { status in ... }` -> ``PHPhotoLibrary.requestAuthorization(`for` = PHAccessLevel.readWrite) { status -> ... }`` (com.moblin.android.platform.avfoundation). `status` is a `PHAuthorizationStatus` enum (`notDetermined`, `restricted`, `denied`, `authorized`, `limited`); switch on it with `when` and `else ->` for `default:`. The handler runs on the main thread.
- `AVCaptureDevice.default(.builtInWideAngleCamera` or `.builtInTelephotoCamera, for: .video, position: .back)` -> `AVCaptureDevice.default(AVCaptureDevice.DeviceType.x, AVMediaType.video, AVCaptureDevice.Position.back)`. When the lenses sit behind one multi-camera it returns that camera, so keep the Swift guards and comparisons as they are.
