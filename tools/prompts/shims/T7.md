## Network.framework shims (T7, package com.moblin.android.platform.network)

- `NWConnection`, `NWEndpoint`, `NWParameters`, `NWProtocolTLS`, `NWProtocolTCP`, `NWProtocolUDP`, `NWInterface` and `NWError` are same-named classes in `com.moblin.android.platform.network`. Import them; never use `java.net.Socket`, `DatagramSocket`, `SSLContext` or `Dispatchers.IO` for a Swift `NWConnection`.
- `NWConnection(to: .hostPort(host: .init(h), port: .init(integer: p)), using: params)` -> `NWConnection(endpoint = NWEndpoint.hostPort(host = NWEndpoint.Host(h), port = NWEndpoint.Port(p)), parameters = params)`. `NWConnection(host: host, port: port, using: params)` -> `NWConnection(host = host, port = port, using = params)`. `NWEndpoint.Port(rawValue: x)` and `.init(integer: x)` -> `NWEndpoint.Port(x.toInt())`; `port.rawValue` is a `UShort` and `port.value` an `Int`; `host.value` is the `String`. `connection.endpoint` exists.
- `NWParameters(tls: options)` and `.init(tls: options)` -> `NWParameters.tls(options)`; `NWParameters(tls: options, tcp: tcpOptions)` -> `NWParameters.tls(options, tcpOptions)`. `NWParameters(dtls: options)` and `NWParameters(dtls: options, udp: udpOptions)` -> `NWParameters.dtls(options)` and `NWParameters.dtls(options, udpOptions)`. `.tcp` and `.udp` -> `NWParameters.tcp` and `NWParameters.udp`. `requiredInterface`, `requiredLocalEndpoint`, `allowLocalEndpointReuse`, `acceptLocalOnly` and `prohibitExpensivePaths` keep their names.
- `NWProtocolTLS.Options()` -> `NWProtocolTLS.Options()`: TLS with the system trust store, hostname verification and SNI. `NWProtocolTCP.Options()` has `noDelay`, `enableKeepalive` and `connectionTimeout`; `NWProtocolUDP.Options()` has no members.
- `NWConnection.State`: `.setup`, `.preparing`, `.ready` and `.cancelled` -> `NWConnection.State.setup` and so on (objects); `case let .waiting(error)` and `case let .failed(error)` -> `is NWConnection.State.waiting` and `is NWConnection.State.failed` with `state.error` (an `NWError`).
- `connection.stateUpdateHandler = f` and `connection.viabilityUpdateHandler = f` keep their names; a method reference is `::f`. `connection.start(queue: q)` -> `connection.start(queue = q)` with the `CoroutineDispatcher` (or `CoroutineScope`) that stands in for the Swift `DispatchQueue`. Every handler and completion runs on that queue.
- `send(content: data, completion: .contentProcessed { error in ... })` -> `send(content = data, completion = NWConnection.SendCompletion.contentProcessed { error -> ... })`; `.idempotent` -> `NWConnection.SendCompletion.idempotent`. TCP sends are written in FIFO order; a UDP send is synchronous on the calling thread.
- `receive(minimumIncompleteLength: a, maximumLength: b) { data, context, isComplete, error in ... }` -> `receive(minimumIncompleteLength = a, maximumLength = b) { data, context, isComplete, error -> ... }` where `data` is `ByteArray?`. `receiveMessage { ... }` has the same completion shape. `batch { }`, `cancel()` and `forceCancel()` keep their names.
- `[weak self]` in an `NWConnection` handler or completion: drop it, never use `WeakReference`. After `cancel()` or `forceCancel()` no handler or completion runs except a final `.cancelled` state. For `RtmpSocket` specifically, the send completion body is wrapped in `if (readyState != RtmpSocketReadyState.closed) { ... }`, which stands in for the released socket.
- `NWInterface` -> `com.moblin.android.platform.network.NWInterface` with `name` and `type: NWInterface.InterfaceType` (`wifi`, `cellular`, `wiredEthernet`, `loopback`, `other`). `NWError` is an `Exception` whose `toString()` is its message.
- `queue.asyncAfter(deadline: .now() + 1) { connection.cancel() }` -> `CoroutineScope(queue).launch { delay(1000); connection.cancel() }`.
