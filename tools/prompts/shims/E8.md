## Motion and LUT files (E8, packages com.moblin.android.platform.coremotion and com.moblin.android.platform.swiftcube)
- CMMotionManager, CMDeviceMotion, CMAcceleration, OperationQueue -> the shims; `startDeviceMotionUpdates(to: q) { data, _ in }` -> `startDeviceMotionUpdates(to = q) { data, _ -> }`; `data.gravity` is in g, iOS axes; `queue.underlyingQueue = processorPipelineQueue` keeps its shape (a CoroutineScope).
- SwiftCube: `SC3DLut(fileData: d)` -> `SC3DLut(fileData = d)`, `SC3DLut(contentsOf: url)` -> `SC3DLut(contentsOf = path)`; both throw SwiftCubeError. `var lut = try SC3DLut(...)`, then `lut.size = n` and `lut.entries = …` keep their shape (`entries` is a List<LutEntry>); `LutEntry(red:green:blue:)` keeps its labels; `try lut.ciFilter()` -> `lut.ciFilter()`, which returns the Core Image shim's CIColorCubeWithColorSpace. `case SwiftCubeError.sizeMissing:` -> `SwiftCubeError.sizeMissing ->`; `case let SwiftCubeError.sizeTooBig(size):` -> `is SwiftCubeError.sizeTooBig -> … error.size`; never redeclare SIMD3, LutEntry, LutType or SwiftCubeError.
- Filter values: CIColorMatrix `rVector`…`biasVector` are CIVector (`.init(x: a, y: b, z: c, w: d)` -> `CIVector(x = a, y = b, z = c, w = d)`); MetalPetal filter `center` and pixellate `scale` are SIMD2 (`.init(a, b)` -> `SIMD2(a, b)`); `MTIColorLookupFilter.inputColorLookupTable` is an MTIImage?; `MTIBlendFilter(blendMode: .normal)` -> `MTIBlendFilter(blendMode = MTIBlendMode.normal)`.
- In LutEffectSuite, `renderBigPngLutWithMetalPetal` renders with GL: put it in an instrumented test class (`app/src/androidTest`, `@RunWith(AndroidJUnit4::class)`), not the JVM suite.
