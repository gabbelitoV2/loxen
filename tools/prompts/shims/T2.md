## Core runtime shims (T2, packages com.moblin.android.media, com.moblin.android.platform.core and com.moblin.android.platform.video)

- `CMSampleBuffer`, `AVAudioPCMBuffer` and `AVAudioCompressedBuffer` -> `MediaSample`. Use its members, never redeclare them as extensions: `sampleBuffer.imageBuffer` (a `CVPixelBuffer?`), `presentationTimeUs`, `durationUs`, `decodeTimeStampUs` (all `Long` microseconds, `kCMTimeInvalidUs` = -1 when invalid), `numSamples`, `format` (the `MediaFormat` that stands in for `formatDescription`), `isKeyFrame`, `replacePresentationTimeStamp(pts)` and `setAttachmentDisplayImmediately()`. `CMSampleBuffer.create(imageBuffer, formatDescription, duration, pts, dts)` stays the existing `create(...)` in `com.moblin.android.common.various`.
- `CVPixelBuffer` and `CVImageBuffer` -> `com.moblin.android.platform.video.CVPixelBuffer` (typealias `CVImageBuffer`). It is an RGBA8 GL texture owned by the pipeline EGL context. `CVPixelBufferGetWidth(b)`/`CVPixelBufferGetHeight(b)` -> `b.width`/`b.height`; `b.size`, `b.isPortrait()` and `b.pixelFormatType` exist. Outside Moblin/VideoEffects/ and VideoEffectsProcessor.swift, readback: `CIContext.createCGImage(CIImage(cvPixelBuffer: b), from:)` plus `UIImage(cgImage:)` -> `b.toBitmap()`; scaled JPEG -> `b.jpegData(longSide, compressionQuality)`. Inside them, keep Swift's Core Image calls; the Core Image shim implements them.
- In files that still import `android.media.Image`, hook G1 makes `Image` a `CVPixelBuffer`; new translations write `CVPixelBuffer` directly and use the CIImage/MTIImage shims for Core Image and MetalPetal.
- `CVPixelBufferPoolCreate(nil, nil, attributes as NSDictionary?, &pool)` -> `pool = CVPixelBufferPoolCreate(attributes)` with a `Map<String, Any>` using `kCVPixelBufferWidthKey`, `kCVPixelBufferHeightKey`, `kCVPixelBufferPixelFormatTypeKey`, `kCVPixelBufferIOSurfacePropertiesKey` and `kCVPixelBufferMetalCompatibilityKey`. `CVPixelBufferPoolCreatePixelBuffer(nil, pool, &buffer) == kCVReturnSuccess` -> `val buffer = CVPixelBufferPoolCreatePixelBuffer(pool) ?: return ...` (or `pool.createPixelBuffer()`), pipeline thread only. `CVPixelBufferPool(width, height, pixelFormatType, maximumBufferCount)` is the direct constructor; buffers return to the pool when they are garbage collected, and `createPixelBuffer()` returns `null` when the pool is exhausted. Pool variables typed `Any?` use `CVPixelBufferPool.matching(existing, sampleBuffer)`.
- `kCVPixelFormatType_32BGRA`, `kCVPixelFormatType_420YpCbCr8BiPlanarFullRange` and `kCVPixelFormatType_420YpCbCr8BiPlanarVideoRange` are `Int` constants in `com.moblin.android.platform.video`; every buffer is RGBA8 whatever the tag.
- `VTPixelTransferSessionCreate(...)` -> drop it (there is no session object). `VTPixelTransferSessionTransferImage(session, from: a, to: b)` -> `VTPixelTransferSessionTransferImage(a, b)`, a scaled GPU copy.
- `CMVideoFormatDescriptionCreateForImageBuffer(allocator:imageBuffer:formatDescriptionOut:)` -> `CMVideoFormatDescriptionCreateForImageBuffer(imageBuffer)`, which returns a `video/raw` `MediaFormat` with `KEY_WIDTH` and `KEY_HEIGHT` and never fails.
- `DispatchSource.makeTimerSource(queue: q)` -> `DispatchSource.makeTimerSource(queue = q)` with a `CoroutineDispatcher` (`PipelineThread.dispatcher` for `processorPipelineQueue`, `q.coroutineContext[CoroutineDispatcher]!!` for another `CoroutineScope` `q`, `Dispatchers.Main` for `.main`). A timer that is never scheduled never fires. `timer.schedule(deadline: .now() + x, repeating: y)` -> `timer.schedule(deadline = DispatchTime.now() + x, repeating = y)`; `setEventHandler(handler = ...)`, `activate()`, `resume()` and `cancel()` keep their names. The timer is fixed-rate and never drifts. `.now() + .milliseconds(n)` -> `DispatchTime.now() + DispatchTimeInterval.milliseconds(n)`.
- `NotificationCenter.default.addObserver(self, selector: #selector(f), name: .N, object: o)` -> `NotificationCenter.default.addObserver(this, N, o) { f(it) }`; `addObserver(forName: .N, object: o, queue: q) { ... }` -> `NotificationCenter.default.addObserver(forName = N, obj = o, queue = dispatcher) { ... }`, which returns the token for `removeObserver(token)`; `removeObserver(self, name: .N, object: o)` -> `removeObserver(this, N, o)`; `post(name: .N, object: o, userInfo: [...])` -> `post(N, o, mapOf(...))`. Notification names are `String` constants. `notification.userInfo?[key]` -> `notification.userInfo[key]`, `notification.object` -> `notification.obj`. All from `com.moblin.android.platform.core`.
- A Swift struct value that is copied and handed on (`$0 = settings`) -> `structCopy(settings)` from `com.moblin.android.platform.core`.
- `processorPipelineQueue` runs on `PipelineThread` (`com.moblin.android.platform.core`). `dispatchPrecondition(condition: .onQueue(processorPipelineQueue))` -> drop it; platform code tests `PipelineThread.isCurrent()`. Host time in microseconds is `HostClock.nowUs()`.
- `CVBufferSetAttachment(buffer, key, value, .shouldPropagate)` -> `CVBufferSetAttachment(buffer, key, value, CVAttachmentMode.shouldPropagate)`, `CVBufferSetAttachments(buffer, attachments as CFDictionary, mode)` -> `CVBufferSetAttachments(buffer, attachments, CVAttachmentMode.shouldPropagate)` with a `Map<String, Any>`, and `CVBufferCopyAttachment(buffer, key, nil) as? String` -> `CVBufferCopyAttachment(buffer, key) as? String` (all in `com.moblin.android.platform.video`). Attachments are stored on the buffer only; they are not written into the pixels. The key constants `kCVImageBufferColorPrimariesKey`, `kCVImageBufferTransferFunctionKey`, `kCVImageBufferYCbCrMatrixKey` and `kCVImageBufferTransferFunction_ITU_R_2100_HLG` are `String`s. `kCVPixelFormatType_420YpCbCr10BiPlanarFullRange` and `...VideoRange` are `Int` constants, but pixel buffers are always 8-bit, so a 10-bit request is served as the 8-bit format of the same range.
