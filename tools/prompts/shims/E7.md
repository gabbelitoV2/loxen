## MapKit (E7, package com.moblin.android.platform.mapkit)
- MKMapCamera, MKMapSnapshotter, MKMapSnapshotter.Options, MKMapSnapshotter.Snapshot -> the shims; `MKMapSnapshotter(options: o)` -> `MKMapSnapshotter(options = o)`; `snapshotter.start(with: DispatchQueue.global(), completionHandler: { snapshot, error in … })` -> `snapshotter.start(with = null) { snapshot, error -> … }` (the completion runs on a background thread; `with = Dispatchers.Main` or a CoroutineScope delivers there); `snapshot.image` is a Bitmap and `snapshot.image.cgImage` -> `snapshot.image.cgImage` (Bitmap identity).
- CLLocation -> android.location.Location: `.coordinate.latitude/.longitude` -> `.latitude/.longitude`, `.coordinate` as a value -> `CLLocationCoordinate2D(latitude = l.latitude, longitude = l.longitude)`, `.speed` -> `.speed.toDouble()`, `.course` -> `(if (hasBearing()) bearing.toDouble() else -1.0)`, `.timestamp` -> `java.time.Instant.ofEpochMilli(time)`, `CLLocation()`/`.init()` -> `Location("")`. CLLocationCoordinate2D -> com.moblin.android.various.utils.CLLocationCoordinate2D (its `translateMeters(x:y:)` extension is in the same package). `Deque<T>` (Collections) -> `ArrayDeque<T>`.
- `MKMapSnapshotter.Options()` with `options.camera = camera`, `options.size`, `options.scale` keeps its shape; `MKMapCamera()` fields `centerCoordinate`, `centerCoordinateDistance`, `heading`, `pitch` are plain vars. Call `cancel()` only where Swift does: a started snapshot still completes and calls its handler after its snapshotter is replaced or dropped, as on iOS; only a still-queued request of a snapshotter nothing references is dropped. `snapshot.point(for: c)` -> `snapshot.point(`for` = c)` (a CGPoint in image points, top-left origin).
