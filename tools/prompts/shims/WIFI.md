## Current WiFi network and location authorization (WIFI, packages com.moblin.android.platform.networkextension and com.moblin.android.platform.corelocation)
- NetworkExtension's `NEHotspotNetwork` has a shim, so its calls are translated, never TODO: `NEHotspotNetwork.fetchCurrent { network in }` -> `NEHotspotNetwork.fetchCurrent { network -> }` with `network?.ssid` (`String`) and `network?.bssid`. The handler runs on the main thread and gets null without WiFi or without location permission, like iOS; it never throws. The macCatalyst CoreWLAN function stays a private function returning null.
- `CLLocationManager()` -> `com.moblin.android.platform.corelocation.CLLocationManager()` with `delegate`, `authorizationStatus` (`CLAuthorizationStatus.notDetermined`, `restricted`, `denied` (also while location services are off, like iOS), `authorizedAlways`, `authorizedWhenInUse`) and `requestWhenInUseAuthorization()`. A `CLLocationManagerDelegate` implements `override fun locationManagerDidChangeAuthorization(manager: CLLocationManager)`. Setting `delegate` is enough: the shim calls the delegate once afterwards and again whenever the authorization changes (the permission, or location turned on or off in Android), like iOS, so a view never calls it itself.
- The shim has no location updates (`startUpdatingLocation`, `desiredAccuracy`, `distanceFilter`, `didUpdateLocations`); Location.swift keeps android.location.LocationManager for those.
