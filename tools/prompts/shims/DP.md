## Document and photo pickers (DP, package com.moblin.android.platform)
- `UIDocumentPickerViewController(forOpeningContentTypes: types, asCopy: true)` with `delegate = model` -> `val launcher = com.moblin.android.platform.DocumentPicker.rememberLauncher(ActivityResultContracts.OpenDocument()) { uri -> com.moblin.android.platform.DocumentPicker.copy(uri) { url -> model.onDocumentPickerUrl?.invoke(url) } }` and `LaunchedEffect(Unit) { launcher.launch(com.moblin.android.platform.DocumentPicker.contentTypes(type)) }`. Never pass `uri.toString()` on: `copy` copies the document into the temporary Inbox under its file name and passes that path on the main thread, as the delegate gets a file URL; it passes nothing on cancel or failure. `rememberLauncher` dismisses the `.sheet` the picker is shown in; a picker that is not the content of its own sheet uses `rememberLauncherForActivityResult` with the same callback.
- A UTType (`.gif`, `.audio`, `.movie`, `.item`, `moblinSettingsFileType`) goes to `DocumentPicker.contentTypes(...)` by its name (`"gif"`, `"audio"`, `"movie"`, `"item"`, `moblinSettingsFileType`), which returns the MIME types; never use a UTType name as a MIME type.
- `UIDocumentPickerViewController(forOpeningContentTypes: [.folder])` -> `rememberLauncher(ActivityResultContracts.OpenDocumentTree())`, launched with `null`, passing `uri.toString()`. `url.startAccessingSecurityScopedResource()` is always true and `stopAccessingSecurityScopedResource()` does nothing. `try url.bookmarkData()` -> `com.moblin.android.platform.Bookmark.data(url)` (ByteArray?, null instead of throwing). `try? URL(resolvingBookmarkData: data, bookmarkDataIsStale: &isStale)` -> `com.moblin.android.platform.Bookmark.resolve(data)` (a java.io.File folder, null when the grant is gone or the disk is not connected); its `.path()` -> `.path`. `folder.appending(component: name)` on such a folder -> `com.moblin.android.platform.Bookmark.child(folder, name)`.
- A recording URL handed on as a string -> `com.moblin.android.platform.Bookmark.url(file)` (String?, a content URI for a file in a bookmarked folder), never `file.toString()`; `url.fileSize` -> `file.length()`; `FileHandle(forWritingAtPath: url.path)` in the recorder -> `com.moblin.android.platform.Bookmark.openOutput(url, file)` (FileOutputStream?).
- `.photosPicker(isPresented: $p, selection: $item, matching: .images)` -> `com.moblin.android.platform.PhotosPicker(isPresented = p, selection = item, matching = ActivityResultContracts.PickVisualMedia.ImageOnly)` (`.videos` -> `VideoOnly`), with `p` a `MutableState<Boolean>` and `item` a `MutableState<Uri?>` (a PhotosPickerItem is a Uri). `item.loadTransferable(type: Data.self)` -> `com.moblin.android.platform.DocumentPicker.loadData(uri)` (suspend, ByteArray? instead of a failure). Never call `contentResolver.openInputStream(uri)` on a picked item directly: it throws for a photo the picker cannot deliver; in a result callback use `com.moblin.android.platform.DocumentPicker.readInput(context, uri)` (InputStream?, the whole photo in memory, null on failure). `item.loadTransferable(type: T.self) { result in ... }` where T's FileRepresentation copies the movie into the temporary directory -> `com.moblin.android.platform.DocumentPicker.loadMovie(uri) { url -> ... }` (not suspend: it runs even after the view is gone, like the Swift completion, and passes the copy's path, or null on failure, on the main thread).
- Put a picker launcher, `PhotosPicker` and the `.onChange` of its selection where the Swift modifier is: inside the NavigationLink destination when the button is there. The view around a NavigationLink leaves composition while its destination is shown, and a launcher registered there cannot be launched.
- `FileManager.default.removeItem(at: url)` in a storage -> `url.let { it.exists() && it.deleteRecursively() }` (false like a throw when nothing is there), never `url.delete()`: a stored item can be a directory (a Live2D model). `moveItem(at: from, to: to)` -> `from.renameTo(to)`, falling back to `from.copyRecursively(to, overwrite = true)` and `from.deleteRecursively()`.
