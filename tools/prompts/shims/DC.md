## libdatachannel, DataChannel and video decoding (DC, packages com.moblin.android.platform.datachannel and com.moblin.android.platform.videotoolbox)

- `import libdatachannel` and `import DataChannel` -> `import com.moblin.android.platform.datachannel.*`. Every libdatachannel function, constant and struct is a top-level declaration with its C name (`rtcCreatePeerConnection(config)`, `RTC_CODEC_H264`, `rtcTrackInit(...)`); never declare `DataChannelNative`, `external` functions, `System.loadLibrary`, stand-in `rtc*` functions, callback interfaces or local `RTC_*` constants.
- `rtcState`, `rtcGatheringState`, `rtcCodec`, `rtcDirection`, `rtcNalUnitSeparator` and the other C enums are `Int` typealiases with `Int` constants (`switch config.codec { case RTC_CODEC_H264: ... }` -> `when (config.codec) { RTC_CODEC_H264 -> ... }`). Every function returns `Int` (negative `RTC_ERR_*` on failure) and never throws.
- `DataChannelConnectionState(value: state)` and `DataChannelGatheringState(value: state)` -> the same call with `value = state` (nullable). Cases keep their Swift names (`.new`, `.connected`, `.inProgress`, `.complete`, ...), so `"\(state)"` prints the same.
- `rtcSetUserPointer(id, Unmanaged.passRetained(self).toOpaque())` -> `rtcSetUserPointer(id, this)`. Callback pointers are `Any?`: `Unmanaged<T>.fromOpaque(pointer).takeUnretainedValue()` -> `pointer as? T`. Pointers are held weakly, and a peer connection's pointer is copied to its tracks as in C.
- Callbacks are Kotlin lambdas with the C parameters: `rtcSetStateChangeCallback(pc) { _, state, pointer in ... }` -> `rtcSetStateChangeCallback(pc) { _, state, pointer -> ... }`, likewise `rtcSetGatheringStateChangeCallback`, `rtcSetTrackCallback` (`pc, tr, ptr`), `rtcSetOpenCallback`/`rtcSetClosedCallback` (`id, ptr`), `rtcSetErrorCallback` (`id, error: String?, ptr`), `rtcChainRembHandler` (`tr, bitrate: UInt, ptr`) and `rtcInitLogger(level) { level, message: String? -> }`; `return` inside is `return@rtcSetXxx`. They run on a libdatachannel thread, and the closed state also synchronously inside `rtcDeletePeerConnection`.
- `rtcSetFrameCallback(tr) { _, data, size, info, pointer in ... }`: `data` is a `ByteArray?` of exactly `size` bytes, so `Data(bytes: data, count: Int(size))` -> `data`, and `info` is an `rtcFrameInfo?`, so `info.pointee.timestamp` -> `info.timestamp` (`UInt`).
- Structs are classes with default arguments, passed without `&`. `iceServers.withCPointers { config.iceServers = $0; config.iceServersCount = Int32(iceServers.count); return rtcCreatePeerConnection(&config) }` -> `iceServers.withCPointers { config.iceServers = it; config.iceServersCount = iceServers.size; rtcCreatePeerConnection(config) }` (`withCPointers` from `com.moblin.android.various.utils`). `rtcTrackInit(direction:codec:payloadType:ssrc:mid:name:msid:trackId:profile:)` takes the `String`s themselves, so the nested `withCString` closures disappear. `rtcPacketizerInit()` fields keep C types: `ssrc`, `clockRate`, `timestamp` are `UInt`, `payloadType` is `UByte`, `cname` is `String?`.
- `uint32_t` parameters are `UInt` (`ssrc`, `rtcSetTrackRtpTimestamp`, `rtcChainRtcpNackResponder`, `rtcRequestBitrate`). Scalar out-parameters are one-element arrays: `var timestamp: UInt32 = 0` + `&timestamp` -> `val timestamp = IntArray(1)` + `timestamp` and `timestamp[0].toUInt()`; `rtcGetTrackRtcpSyncTimestamps` takes two `LongArray(1)`.
- Output buffers are `ByteArray?` plus size: `rtcGetLocalDescription(pc, nil, 0)` -> `(pc, null, 0)`, `[CChar](repeating: 0, count: n)` or `Data(count: n)` with `withUnsafeMutableBytes` -> `ByteArray(n)`, and `String(cArray: b)` or `String(bytes: b, encoding: .utf8)` -> `stringFromCArray(b)` (`com.moblin.android.various.utils`). `message.withUnsafeBytes { rtcSendMessage(tr, $0.bindMemory(to: CChar.self).baseAddress, Int32(message.count)) }` -> `rtcSendMessage(tr, message, message.size)`.
- A thrown `String` in a file that imports libdatachannel -> `throw DataChannelError(message)`, whose `toString()` is the message. A Swift `deinit` of an object retained with `passRetained` never runs on iOS; drop it.
- `AVAudioConverter.create(from = compressedFormat, to = makePcmFormat(rate, channels))` decodes: `converter.convert(to = pcmBuffer) { compressedBuffer.data }` puts one Opus or AAC packet as 16 bit PCM in `pcmBuffer.data` (a new array per call). Opus needs no `csd-0`, AAC needs it. `pcmBuffer.makeSampleBuffer(pts)` -> `pcmBuffer.replacePresentationTimeStamp(pts)`.
- `VTDecompressionSessionCreate(allocator:formatDescription:decoderSpecification:imageBufferAttributes:outputCallback:decompressionSessionOut:)` -> `val (status, session) = VTDecompressionSessionCreate(allocator = null, formatDescription = f, decoderSpecification = d, imageBufferAttributes = a, outputCallback = null)`, a `Pair<Int, VTDecompressionSession?>`; `kVTVideoDecoderSpecification_EnableHardwareAcceleratedVideoDecoder: kCFBooleanFalse` -> `... to false`. `VTDecompressionSessionDecodeFrame(s, sampleBuffer:flags:infoFlagsOut:outputHandler:)` -> `VTDecompressionSessionDecodeFrame(s, sampleBuffer = b, flags = f, outputHandler = h)` without `infoFlagsOut`; `VTDecodeFrameFlags` and `VTDecodeInfoFlags` hold `Int` constants (`[._A, ._B]` -> `VTDecodeFrameFlags._A or VTDecodeFrameFlags._B`). The handler `{ status, infoFlags, imageBuffer, presentationTimeStamp, duration -> }` runs on the pipeline thread with a leased RGBA `CVPixelBuffer` and microsecond times; frames before the first key frame fail with `kVTVideoDecoderBadDataErr`. The `defaultDecodeFlags`, `decodeFrame` and `invalidate()` extensions are in `com.moblin.android.media.haishinkit.extension`.
